# Сайт-приглашение: ответы гостей и управление через Telegram

## Что добавлено
- Каждый новый ответ сохраняется в PostgreSQL и отправляется в Telegram-группу.
- В группе команда `/guests` показывает список сохранённых ответов с пагинацией.
- У каждого гостя есть кнопка удаления с подтверждением.
- `/delete ID` предлагает удалить одну запись по ID.
- `/delete_all` предлагает очистить список целиком; действие требует подтверждения.
- Удаление записи также пытается убрать соответствующее сообщение бота из группы. Telegram может не разрешить удалить старые сообщения, но сама запись будет удалена из базы.
- Управление доступно только указанным `TELEGRAM_ADMIN_USER_IDS` и только в чате `TELEGRAM_ADMIN_CHAT_ID` или `TELEGRAM_CHAT_ID`.
- Webhook бота настраивается автоматически при запуске на Render через `RENDER_EXTERNAL_URL`.
- Токен Telegram и строка подключения к базе не публикуются в коде страницы.

## Важно про старые ответы
Бот API не может сам прочитать всю старую историю группы. Поэтому база начнёт собирать ответы после установки этой версии. Уже отправленные ранее сообщения останутся в истории группы, но автоматически в список `/guests` не попадут; при необходимости их можно добавить в базу вручную отдельно.

## 1. Создай PostgreSQL базу
В примере используется Supabase PostgreSQL:
1. Создай проект на https://supabase.com/dashboard.
2. Открой **Connect** и скопируй PostgreSQL connection string (предпочтительно Session Pooler, если соединение с Render не работает через прямой хост).
3. Используй строку как `DATABASE_URL` в Render. Она должна быть URI вида `postgresql://...` и включать SSL-параметр, если его выдаёт Supabase.
4. При первом запуске сервер сам создаст таблицу; SQL вручную запускать не нужно.

План Supabase Free может приостанавливать проект после периода низкой активности; его можно возобновить в панели. Следи за уведомлениями и сделай экспорт базы, если список важен.

## 2. Переменные Render
Открой Render → нужный Web Service → **Environment** и добавь/проверь:

- `TELEGRAM_BOT_TOKEN` — секретный токен от BotFather.
- `TELEGRAM_CHAT_ID` — ID общей Telegram-группы, в которую бот уже отправляет RSVP.
- `TELEGRAM_CHAT_ID_2` — необязательный дополнительный получатель, если он действительно нужен.
- `DATABASE_URL` — PostgreSQL URI из панели базы.
- `TELEGRAM_WEBHOOK_SECRET` — случайная строка только из латинских букв, цифр, `_` и `-` (например, сгенерируй в менеджере паролей).
- `TELEGRAM_ADMIN_USER_IDS` — числовые user ID организаторов через запятую, например `111111111,222222222`. Здесь нужны личные user ID двух аккаунтов, НЕ ID группы. Узнать можно через `@userinfobot`.

Для команд в группе `TELEGRAM_CHAT_ID` должен быть ID этой группы (обычно отрицательное число вида `-100...`). Если уведомления уже приходят в группу, оставь это значение как есть.

Сохрани переменные с **Save, rebuild, and deploy** или аналогичной опцией, которая запускает новое развёртывание.

## 3. Обнови GitHub
Заменить файлами из этого обновления:
- `server.js`
- `package.json`
- `render.yaml`
- `.env.example`
- `.gitignore`
- `index.html`
- `README.md`

Папки сайта (`Data`, фото, декор и шрифты) оставь без изменений. Не загружай `.env` или токены в GitHub.

После push в GitHub дождись успешного деплоя Render. При старте сервер создаст таблицу, зарегистрирует webhook и задаст команды бота.

## 4. Команды в Telegram-группе
Используй настоящий username своего бота вместо `ИмяБота`:

- `/guests@ИмяБота` — показать список. Перелистывай страницы кнопками.
- Нажми `🗑 Удалить #ID` рядом с нужной записью и подтверди удаление.
- `/delete@ИмяБота 12` — запросить подтверждение удаления записи №12.
- `/delete_all@ИмяБота` — запросить подтверждение очистки всего списка.
- `/help@ИмяБота` — помощь.

Если username бота явно указан в командe, Telegram получает команду даже при включённом privacy mode в группе.

## Диагностика
Открой `https://АДРЕС-ТВОЕГО-RENDER/api/health`. В успешном случае должны быть `databaseConfigured: true`, `databaseReady: true`, `managementWebhookConfigured: true`, а `adminUsersConfigured` должен соответствовать числу добавленных ID.

Если `databaseReady` — `false`, проверь `DATABASE_URL` и логи сервиса Render. Не показывай никому `DATABASE_URL` или токен бота.
